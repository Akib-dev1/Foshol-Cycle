## Non-blocking observations

1. **Duration reference point is preserved, not confirmed.** The `decision_duration_source` values (`BR11_VARIETY`, `VARIETY_APPROX_140_DAYS`, etc.) identify sources, not whether the duration starts at sowing, transplanting, or another stage. E1 correctly does not guess. The timeline evaluator must treat the reference point as unresolved and mark timing conditional unless a source explicitly resolves it; `E1-builder.md` should record this as an open evidence item rather than implying §18 item 1 is fully closed.
2. **Evidence-quality flags are raw-only.** `turnaround_rule_status` is `VALIDATION_REQUIRED` for all 8 rows, and `date_precision`, `window_basis`, and `hard_deadline_validated` are also preserved only in `raw`. Current `turnaround_days_*` cells are blank, so E1 exposes no numeric preparation time. If future data supplies turnaround values, the normalized profile would expose the numbers without the validation flag; downstream must read `raw` or the loader must normalize the status before §10.2 timing is implemented.
3. **No dedicated preservation tests.** The suite tests loading, excluded crops, names/variety, windows, duration integers, and null/unclear handling, but not the §10.1/§11 preservation of `decision_duration_source`, `duration_precision`, `establishment_method`, `seedling_age_*`, `family`, `is_legume_n_fixing`, or the rotation text. The code is generic and the manual check passes; a regression test would lock these guarantees.

## Verdict

**PASS** — E1's loader/normalizer meets the specified preservation, null-handling, and no-guess rules. The only open item is evidence confirmation of the duration reference point, which E1 correctly leaves unresolved rather than guessing.
