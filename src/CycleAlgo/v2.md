# Fosol-Cycle v2 — Weather-Aware Interactive Crop-Sequence Explorer

> **Status:** Implemented and independently checked for hackathon frontend integration.
> This is an exploration prototype, not a field-validated agricultural recommendation system.
>
> **Pilot:** Rajshahi, Bangladesh, using eight existing crop profiles and a representative NASA POWER location.
>
> **Relationship to v1:** [v1.md](v1.md) remains the original implementation specification.
> This document records what v2 actually delivers, how to connect it, and what remains unsupported.

## 1. What the engine does

The user chooses a start date, first crop, water-access scenario, and comparison preference.
The engine generates possible sequences of exactly three crops:

```text
First crop → Second crop → Third crop
```

It returns dated schedules, checks, historical weather comparisons, conditions,
sources, and missing evidence. There is **no three-sequence total limit**.
Counts depend on the selected inputs and engine policy.

The engine does not assess an existing standing crop or confirm that the user's
field is ready. Planting and preparation assumptions must remain visible.
Third-to-first compatibility is not checked: a three-crop sequence is not proof
of an indefinitely repeatable rotation.

## 2. Changes delivered in v2

### Reliable schedules and evidence handling

- Correct chronological completion calculations and example schedules.
- Preparation, soil, and duration-reference verification remain trusted server inputs,
  not facts a browser request can declare verified.
- Unknown preparation does not become zero preparation time. Window-only gaps are
  distinguished from confirmed field-ready waiting.
- Missing agricultural evidence remains conditional, unknown, or unavailable.
- Planning dates outside `0002-01-01` through `9990-12-31` return HTTP 400.
  These are technical calendar limits, not NASA weather coverage or agronomic validation.

### NASA weather affects comparisons

- The server uses NASA POWER API history/cache, not the local environmental CSVs.
- Default location: **24.3767 N, 88.6029 E**. This represents a point/grid, not a district average.
- Stable historical request: **1991-01-01 through 2025-12-31**.
- Cache reuse, stale-cache warnings, and unavailable-data behavior are explicit.
- Local environmental CSVs remain separate offline test/demo fixtures; there is no silent production fallback.
- Temperature and rainfall coverage and units are checked independently.
- Common complete historical seasons are used for each weather ranking group.
- Missing observations are not zero-filled. Missing temperature does not disable valid rainfall views, or vice versa.

### Separate comparison preferences

| Preference | Meaning | Status |
|---|---|---|
| `fastest_completion` | Compare supported completion timing | Implemented |
| `more_crop_diversity` | Compare crop-family diversity, with legume context | Implemented; not a measured soil-health score |
| `closest_temperature_match` | Compare seasonal median temperature with general EcoCrop optimum guidance | Implemented; exploratory species-level proxy |
| `least_dry_spell_exposure` | Compare longest dry-day runs within growing periods | Implemented; not irrigation demand or drought damage |
| `least_heavy_rain_exposure` | Compare heavy-rain days per valid growing day | Implemented; not waterlogging or crop damage |
| `lowest_total_cost` | Compare sourced total costs | Accepted preference, but unavailable without sufficient evidence |
| `highest_net_return` | Compare sourced potential net returns | Accepted preference, but unavailable without sufficient evidence |
| `least_irrigation_dependence` | Compare validated irrigation dependence | Accepted preference, but unavailable without sufficient evidence |

`lowest_upfront_cash` remains rejected until the required cash-flow evidence exists.
Unsupported comparison controls must be disabled with a reason, not shown with invented scores.

Weather definitions:

- **Dry day:** `PRECTOTCORR < 1 mm/day`.
- **Heavy-rain day:** `PRECTOTCORR >= 20 mm/day`.
- Rain indices are growing-period adaptations, not standard annual Climdex outputs.
- Temperature uses the growing-period median of daily `T2M`, not stage-specific heat thresholds.
- Branch weather values use equal weighting of the three crop summaries.
- Comparisons use the higher exposure of `min_realization` and `max_realization`,
  two completion-optimized example schedules. This is **not** a worst-case bound over all schedules.

There is **no overall best-rotation score**. Ties remain ties; candidate and
conditional paths remain separate; unavailable evidence is not ranked as zero.
Changing water access affects checks and cautions, but does not establish a
validated irrigation-based weather ordering.

### Performance and transport

- Repeated weather calculations reuse an existing request-local cache.
- Large HTTP responses use gzip when the client accepts it; JSON fields are unchanged.
- Clients without gzip still receive ordinary JSON. Browsers negotiate decompression automatically.
- Recorded local Boro benchmarks improved from roughly **3–11 seconds** to
  **1.4–6 seconds** for direct-engine calls across four tested preferences.
- A tested climate response transferred about **0.97 MB with gzip**, versus **6.76 MB** uncompressed.

These are local measurements, not a production performance guarantee. A loading
indicator is still needed. Complete before/after response comparisons for the
four tested preferences were identical.

## 3. Interactive website integration

Use **`POST /api/explore`**, not the featured demonstration JSON.

```json
{
  "district_id": "rajshahi",
  "start_date": "2026-11-06",
  "first_crop_id": "mustard_binasarisha9",
  "water_access": "unknown",
  "preference": "least_dry_spell_exposure"
}
```

1. Send `first_crop_id: null` to obtain starting crop options and a summary.
   `branches: []` is intentional at this stage, not an engine failure.
2. Selecting a first crop returns its generated three-crop paths.
3. Changing the date, first crop, water scenario, or preference requires a new request.
4. Second/third crop selections can filter or group returned paths; they are not separate API inputs.
5. Show ties, conditional status, unavailable evidence, schedule dates, waits, sources,
   and historical coverage honestly. Never label the first listed path a guaranteed recommendation.
6. Prevent an older response from replacing results for newer user selections.
   Do not silently fall back to static demonstration results on an API error.

The API schema version remains **`"1"`**; the product name v2 does not change it to `"2"`.
Other districts return unsupported status rather than borrowing Rajshahi crop rules.
Use a same-origin proxy or the documented origin policy; do not broadly open CORS.

Start the development API from `fosol-cycle-engine/`:

```powershell
python -X utf8 -m src.server --host 127.0.0.1 --port 8000
```

## 4. Optional featured comparison

[featured_comparison.json](fosol-cycle-engine/examples/featured_comparison.json)
contains three fixed-scenario examples, generated through the shared engine using
the API-sourced POWER cache:

| Example | Sequence | Agricultural evidence scope |
|---|---|---|
| Baseline | Mustard → Boro → T. Aman | Documented Rajshahi regional pattern |
| Alternative A | Mustard → Mung → T. Aman | Khulna/Satkhira context; Rajshahi applicability unverified |
| Alternative B | Wheat → Mung → T. Aman | Documented Kushtia sequence explored under Rajshahi weather/reference profiles; local applicability unverified |

These are optional explanatory examples, **not a restriction on interactive results**.
They use start date `2026-11-06` and unknown water access. Their weather views share
34 complete historical seasons, 1991–2024; cross-year schedules can exclude the
final season even though the cache extends through 2025.

Each featured view's headline, schedule values, relevant per-crop details, and
year list use the same common-period engine calculation. An unavailable view has
null values and a reason; other available views remain usable.

The saved temperature comparison is an exact three-way tie at 0 °C distance.
That means seasonal medians fall within general guidance, **not** absence of heat stress.
Do not compare unequal sequence-period totals as annual savings.

Sources, schedules, values, and agricultural caveats are in the
[worked explainer](fosol-cycle-engine/docs/EXPLAINER.md).

## 6. Remaining limits and readiness

**Ready:** Connect an interactive hackathon frontend to the API within the stated scope.

**Not established:**

- Farm-specific soil, drainage, preparation, irrigation supply, or economic feasibility.
- Locally validated variety/stage-specific weather-damage rules or alternatives.
- Yield, profit, future weather, or irrigation-demand predictions.
- Third-to-first compatibility or long-term rotation benefits.
- Production hosting security, simultaneous-user capacity, or frontend correctness.

SMAP, when supplied, is context only and does not affect ranking. POWER `GWETTOP`
is MERRA-2 surface wetness, not SMAP or measured root-zone moisture.

The correct claim is: **explore possible sequences and compare supported evidence**,
not **identify the best rotation for a particular farm**.
